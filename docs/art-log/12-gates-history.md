## 12. Testing and quality gates (before 2026-09-25)

The headless gate is `res://tests/smoke_test.gd`. It verifies Mobile configuration, logical viewport size, roster/device routing, offline authority, curated-asset provenance, production scenes, player physics, compact HUD geometry, the camp, eight unique structure textures, the secluded forest start, readable night light, environment atlases, projectile lifecycle, and source audio. On the current polish revision it passes as `SMOKE OK (207 checks)`. Focused gates also pass for weighted auto-aim (46), tower/trap combat (70), enemy presentation identities (44), enemy impact and health bars (42), the VFX director (133), health readability (67), the damage response (35), the impact camera (21), three-to-five-step resource progress (72), safe-area HUD/deck layout (52/58), co-op hardening (33), the world map (169), the Poly Haven district (58), the Poly Haven environment (36), the local environment family (47), terrain materials (35), the promoted asset pipeline (66,537), and desktop ENet replication. Fresh Mobile/Vulkan contact sheets cover enemy, defense, dashboard, and every build category. Desktop gates prove only the contracts they inspect and do not prove Android rendering, audio perception, thermals, touch ergonomics, or physical two-device synchronization.

The integrated showcase retains `res://tests/render_validation.tscn`, while `res://tests/world_render_validation.tscn` is the focused world GPU gate. It writes twenty-five Mobile/Vulkan captures at the exact 480×270 logical size: overview; Kaupunki and Ostari districts; camp and camp-satellite composition by day/night; city salvage; concrete barrier day/night; forest rock and log; city-building detail; long Ostari shell; west/east villages by day; west village at night; local car wreck; city-to-forest terrain transition; central road shoulder; city, forest and wilderness density; and wilderness ecology against gameplay by day/night. The set was stale for a while and the reason is worth keeping: the gate reads `BesprenWorldMap2D.STARTING_CAMP_POSITION` live, so the camp relocation to `(9950, 2400)` was already correct in the scene while every PNG on disk still showed `(11264, 1536)` - a capture gate proves nothing about the build until it is re-run, and the Godot MCP `run_project` quota had blocked that. It does not need the MCP runner. Godot renders these by being pointed at the scene without `--headless`, which is how the current set was produced.

```powershell
& 'C:\Users\heikk\Desktop\Godot_v4.7.1-stable_win64.exe' `
  --headless --editor --path 'C:\Users\heikk\Desktop\Claude\gpt_peli' --import --quit

& 'C:\Users\heikk\Desktop\Godot_v4.7.1-stable_win64.exe' `
  --headless --path 'C:\Users\heikk\Desktop\Claude\gpt_peli' `
  --script res://tests/smoke_test.gd
```

Godot’s [command-line documentation](https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html) defines `--headless`, `--import`, `--script`, and project-path behavior. A dummy headless renderer can prove loading and deterministic logic without proving final pixels. The source export closure lists 201 unique runtime resources, and `runtime_export_dependencies.tscn` strongly retains those resources plus the closure manifest as 202 dependencies; every listed path resolves and the scene's declared and retained counts agree. `polyhaven_district_validation.gd` now derives the dependency figure from the resource figure instead of authoring both, because the two can only ever differ by that one manifest. Both artifacts are hand-maintained, which is exactly why they go stale silently: a script reached only through a `class_name` and a `.new()` call is invisible to a scene-graph dependency walk, so `camera_shake_2d.gd`, `vfx_director.gd`, `actor_ground_shadow_2d.gd`, and `health_bar_2d.gd` all shipped into the runtime while being named in neither artifact until they were added here - and the gate that reads those artifacts sat at 194/195 through the same period, passing only because nobody had re-run it against the closure it was meant to pin. Repointing the roster earlier meant dropping the eight retired pixel-art/fantasy scenes with their twenty-two source textures and naming the baked family instead: eight actor scenes, eight `SpriteFrames`, fifty-two sheets, and `actor_facing.gd`. The last packaged artifacts, `build/android/Bespren-actor-roster.pck` and its 54.29 MiB `.apk`, passed isolated closure loading (173 resources, 23 scenes instantiated), the inventory gate with zero forbidden payload entries, and APK Signature Schemes v2/v3 - but they were built before the feedback stack existed and therefore predate the current closure. A repackage and re-verification is open alongside physical-device rendering/performance/touch/lifecycle/two-device certification.

## 13. Toolchain audit (before 2026-09-25)

Godot `4.7.1.stable.official.a13da4feb` remains the validation runtime. The current overhaul uses the local console runner for both evidence classes: `--headless --script` for the deterministic gates and the same binary without `--headless` for the twenty-five Mobile/Vulkan pixel captures. That removed the Godot MCP `run_project` quota from the critical path, and the capture set is current with the code rather than trailing it. Both desktop evidence classes remain separate from Android-device rendering, thermals, safe-area ergonomics, and physical two-device LAN behavior.

Blender `5.0.0` is connected through BlendMCP, including Poly Haven catalog acquisition/import for the reviewed environment sources. The MCP-created nature workshop is saved at `tools/art/blender/bespren_map_asset_workshop.blend`, the immutable Hidden Alley source workshop at `tools/art/blender/bespren_polyhaven_district_workshop.blend`, and the local-vault workshop at `tools/art/blender/bespren_local_environment_workshop.blend`; checked-in Python performs all three repeatable camera/light/style bakes. Camp, character, and defense generation retain their isolated-scene policies, while each environment renderer requires its dedicated workshop/source contract. This protects unrelated user scenes and makes all derived PNG/atlas families reproducible without requiring Blender or MCP at game runtime.
